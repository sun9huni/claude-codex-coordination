# .agent/handoffs/ — cross-session continuity

Chat sessions are not durable. This directory keeps the bridge.

| File | Role |
|---|---|
| `../status/<slice>.md` | The authoritative per-slice baton: owner/heartbeat/remaining_actions. `handoff.sh <agent> <slice>` refreshes it. |
| `CURRENT.md` | DERIVED lab-wide index (generated by `scripts/status.sh index`) of which session owns which slice. NEVER hand-edited — edit the per-slice `.agent/status/<slice>.md` batons instead. |
| `OWNER.lock` | flock target. `handoff.sh` acquires it (exclusive, 30s timeout) so two snapshots cannot interleave. Empty file; not tracked. |
| `handoff.md` | The protocol: what fields are required, when to hand off, what's forbidden. |
| `takeover-prompt.md` | What an incoming agent does when continuing someone else's work. |
| `state/sessions/<ts>-<agent>/` | Per-handoff snapshot dir: `git-status.txt`, `git-log.txt`, `diff.patch`, `diff-staged.patch`, `session-note.md`, `meta.txt`. Rotated to most recent 20. |
| `state/latest` | Symlink to the newest snapshot dir. |
| `archive/` | Optional; move stale CURRENT.md + state here when starting a new chapter. |

## Lifecycle

```
Session start
  └─ Read the CURRENT.md index (who owns which slice), then your
     status/<slice>.md baton
  └─ (If owner_agent ≠ you) Open takeover-prompt.md, run steps 4-7
  └─ Optionally re-read state/diff.patch, state/git-status.txt to
     verify nothing has drifted since the prior session

Mid-session
  └─ Work happens in project repos
  └─ your status/<slice>.md baton is the running notebook for your slice

Session end
  └─ Update your status/<slice>.md baton (or call /handoff to be guided)
  └─ Run ./scripts/handoff.sh <next-agent> <slice>
  └─ Run ./scripts/status.sh index to regenerate CURRENT.md
  └─ Stop hook validates frontmatter on the way out
```
