# Operating Policies

Standing rules that apply across every project unless an `AGENTS.md` in
that project overrides them.

## A. Large work → plan first

Any task that touches ≥ 5 files, refactors, changes domain rules, or
will exceed ~30 minutes requires a contract under `.agent/contracts/`
approved by the human before implementation begins. Use the
`exec-plan` skill.

## B. No verification → not done

A task is not complete unless a verification command ran and either
passed or its failure was explained. If no verify path exists for the
touched area, the first step of the task is to create one.

## C. Generation and verification are separate

The agent that wrote the code should not be the only one signing off
on it. Use the `review-skeptical` skill, a sibling agent, or — at
minimum — a re-read of the diff against the contract before claiming
done.

## D. Fix the system, not the symptom

If the same bug, miss, or correction appears three times, the next
edit is to a rule, checklist, skill, eval case, or script — not to
another patch. Promote patterns instead of repeating them.

## E. The harness must stay small

Unused rules, skills, tools, checklists are deleted. Aim for a harness
that fits in working memory. Adding a new skill requires removing or
merging one that is unused.

## F. Approval gates

Stop and ask before:

- DB schema or destructive migration
- Production deploy or release
- Secret / credential rotation
- External side effects (Slack, email, third-party APIs)
- SLURM submission of expensive jobs
- Force-push, history rewrite, branch deletion
- `/mnt/data` writes outside an owned subtree (see memory:
  `feedback_file_permissions.md`)

## G. Diagnose before scaling compute

For FKSFold / FragMap / GCMC / MMGBSA work, do not propose a 10×
rerun before zero-compute diagnostics and a smoke run. See memory:
`feedback_compute_scaling.md`.

## H. Slurm vs inline

Heavy / GPU work goes via SLURM. Read-only inspection and small MDA
analysis runs go inline. See memory: `feedback_slurm_usage.md`.

## I. Session state lives in the repo

End-of-session, agent switch, or context near limit must produce an
updated `.agent/status/<slice>.md` + `scripts/handoff.sh <agent> <slice>`
snapshot (CURRENT.md is regenerated by `scripts/status.sh index`).
Chat history is never authoritative.
