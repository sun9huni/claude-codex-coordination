# Concurrent-session handoff — per-slice batons + derived index

## Purpose

`.agent/`를 공유하는 동시 Claude 세션들이 각자 슬라이스를 소유하고
write-contention·cross-slice leak 없이 핸드오프할 수 있게 한다. 현재
구조(단일 `CURRENT.md` 배턴)는 직렬 멀티-툴 핸드오프(Claude→Codex→Cursor)
전제라, 병렬 세션에서 (a) `active_slice` scalar로 인한 슬라이스 누수,
(b) 단일 파일 동시 편집 lost-update, (c) `owner_agent` scalar로 claude 2세션
구분 불가 — 세 가지가 깨진다. 이 변경은 배턴을 슬라이스 수만큼 쪼개고
`CURRENT.md`를 파생 인덱스로 만들어 셋을 해소한다.

## Assumptions And Questions

- assumptions:
  - 동시 세션은 `.agent/`를 **공유** (worktree 격리 아님) — 사용자 확인됨
  - 공유를 택한 것 = lab-wide 가시성을 원함 → 단일 인덱스 뷰 유지가 맞음
  - 세션은 자기 슬라이스 status 파일만 쓰면 contention 0 (서로 다른 파일)
  - `scripts/status.sh`가 frontmatter 스캔해 인덱스 렌더 가능 (기존 스캔 확장)
- open questions:
  - heartbeat "fresh" 임계값 — 30분? 세션 idle 패턴에 따라 조정 (구현 시 기본 30min, 설정 가능)
  - 같은 슬라이스 2세션 경고를 SessionStart에서만 vs Stop에서도 (1차: SessionStart만)
- tradeoffs:
  - 경고-only(자동 lock 없음): 단순하지만 사람이 무시하면 여전히 충돌 가능. 수용 — 진짜 lock은 과한 기계장치(#3 out of scope)
  - 인덱스 파생화: CURRENT.md를 손으로 못 고침 → ritual "CURRENT.md 편집"하던 근육 기억 변경 필요. 문서로 보완

## Constraints

- allowed change scope:
  - `.agent/status/<slice>.md` × 5 — frontmatter 추가 (owner_session/agent/version/remaining_actions/contract_pointers/heartbeat)
  - `.agent/status/README.md` — per-slice frontmatter 규약 문서화
  - `.agent/handoffs/CURRENT.md` — 인덱스 포맷으로 재생성 (마이그레이션)
  - `.agent/handoffs/takeover-prompt.md` — per-slice liveness 모델로 갱신
  - `.agent/handoffs/handoff.md` — 필드 요구사항 갱신
  - `CLAUDE.md`, `WORKFLOW.md §0/§1` — 3-step ritual + routing 문구 갱신
  - 훅: `stop-handoff-check.sh`(active slice status 검증으로), `session-start-decay-check.sh`(claim-check 추가) + 신규 claim-check 로직
  - `scripts/handoff.sh`(per-slice 스냅샷 + heartbeat), `scripts/status.sh`(인덱스 생성)
  - `.agent/contracts/_template.md` — 변경 없음(슬라이스 컨트랙트 무관)
  - `tests/run-harness-concurrency.sh` — 신규 테스트
- forbidden change scope:
  - 슬라이스 정의/경계 변경 금지 (taxonomy 동결)
  - `src/`, project repo 무관 파일 미접촉
  - Codex 미러(`AGENTS.md` 본문 규칙, `skills/`) 동기화 금지 (별도)
  - template repo 반영 금지 (별도)
- external constraints:
  - 3-step session ritual backward-compatible — CURRENT.md는 *읽으면 인덱스가 보이는* 형태로 존속 (삭제 금지)
  - 새 외부 의존성 0 (bash + 기존 훅 인프라)
  - 마이그레이션 직후 단일-세션 워크플로 회귀 없어야 함

- unrelated code touched: 없음 (project src 무관)
- pre-existing dead code noticed: 해당 없음
- request-to-diff trace: 사용자 "slice가 합쳐진 것 같다 → 왜 → 동시 세션엔 단일 CURRENT.md 부적합 → Option A spec"

## Risks

- regression risk: Stop hook을 active-slice 검증으로 바꾸며 단일 세션 워크플로 깨질 수 있음 → Step 5에서 backward-compat 명시 검증
- integration risk: `status.sh` 인덱스 생성이 frontmatter 파싱 실패 시 CURRENT.md 손상 → 생성 실패 시 기존 CURRENT.md 보존(atomic write)
- hidden dependency risk: 다른 스킬/문서가 `CURRENT.md`의 `active_slice` scalar를 파싱할 수 있음 → grep로 의존처 전수조사 후 갱신

## Rollback

- revert strategy: 마이그레이션 전 `state/` 백업한 CURRENT.md 복원 + status frontmatter 제거 + 훅/스크립트 git revert
- containment strategy: Step 1에서 백업 선행. **단 마이그레이션 후 동시 세션이 새 포맷으로 핸드오프를 쓰기 시작했다면 그 내용은 status 파일에 남으므로 git revert로 안 지워짐 → 수동 회수 필요** (Red Flag 인지). 따라서 마이그레이션은 다른 세션 idle일 때 1회 수행 권장
