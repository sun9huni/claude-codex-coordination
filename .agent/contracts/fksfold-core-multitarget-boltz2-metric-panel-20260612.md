# Multi-target Boltz-2 vs AIGEN-Fold Metric Panel

## Goal

Build a minimum-10-case comparison table for pure Boltz-2 baseline vs AIGEN-Fold
steering. The primary metric is CRBN-target DockQ where a held-out crystal GT is
available. iPTM and complex_ipDE are mandatory confidence fields for every
generated row.

## Scope

- Use the local git repo for small harness/scoring edits only.
- Use the shared workspace for GPU outputs and staged run assets.
- Reuse existing held-out PDB/YAML assets where possible.
- Do not overwrite or delete existing output roots.

## Panel

Primary independent PDB held-out set:

- 9NYR, 9NGT, 9NFQ, 9OS2, 9W2F, 9DWW, 9DUR

Expansion to reach at least 10 generated cases:

- Add existing VAV1/9NFR and 9D0W-style cases if a GT/scorer path is already
  available.
- If no immediate DockQ GT path exists for expansion cases, still run them for
  iPTM/ipDE and mark DockQ as `NA_unscored`; the report must separate
  `DockQ-scored targets` from `confidence-only expansion cases`.

## Conditions

- `boltz2_baseline`: no interface steering, no biophysical_hybrid.
- `aigen_biophysical_hybrid`: interface_scoring_type=biophysical_hybrid,
  interface_lambda=20, num_particles=8, interface_resampling_interval=3,
  sampling_steps=50, diffusion_samples=1.
- Single seed first: seed=42 for all cases.
- If time allows, seed=16/123 can be added only after first-pass completion.

## Required Output Columns

- case_id, target_id, condition, seed
- output_pdb, confidence_json
- DockQ, DockQ_status
- iptm, complex_ipde, ligand_iptm, protein_iptm, confidence_score
- pair_chains_iptm if present
- generation_status, notes

## SLURM Plan

- OUT_BASE: `/mnt/data/users/ubuntu/workspace/multitarget_boltz2_aigen_metrics_20260612`
- QoS: `batch`
- Node/GPU count: 1 node, up to 8 A100 GPUs via job array `%8`
- Wall time: 2 hours for first pass
- Dependency chain: none for generation; scoring runs after generation completes
- Stop condition:
  - stop when at least 10 cases have both conditions attempted and at least
    7 independent PDB targets have DockQ scored, or
  - stop early if the first 8 generated tasks fail for the same infrastructure
    reason (image/mount/GPU) and do not keep burning GPU.

## Done When

- A manifest exists under OUT_BASE describing all attempted case/condition/seed rows.
- Generation logs and outputs exist under OUT_BASE.
- A summary TSV/CSV exists with DockQ primary metrics and mandatory iPTM/ipDE fields.
- Any DockQ-unscored expansion cases are clearly labeled and excluded from the
  DockQ claim.

## Verification

- `bash -n` on any generated SLURM script.
- Dry-run manifest count before submission.
- After generation: count completed `*_model_0.pdb` and `confidence_*_model_0.json`.
- Run DockQ scorer on all held-out PDB rows with GT CIFs.
- Report missing/failing rows explicitly.

## Risks

- The repo is dirty; avoid unrelated files and do not normalize deletions.
- Only seven independent held-out PDB targets are currently confirmed locally.
- Confidence metrics are generated by the model and may not correlate with DockQ;
  they are required fields, not primary proof of structural correctness.
- Some older SLURM scripts may mount stale code; use explicit source mounts or
  a known image path and smoke-gate logs.

## Rollback

- `scancel <jobid>` if the array misbehaves.
- Remove only the new OUT_BASE after explicit user approval.
- Revert local harness/scoring edits if they are wrong; do not touch existing dirty files.
