# Claude Entry Point

This file is Claude Code's entry to `/home/ubuntu`. Codex/Cursor use
`AGENTS.md` directly; Claude uses this file plus its native primitives
in `.claude/`. Working state is per-slice: each `.agent/status/<slice>.md`
is the authoritative baton for its slice (schema in
`.agent/status/README.md`). `.agent/handoffs/CURRENT.md` is the entry
view — a DERIVED lab-wide index, generated by `scripts/status.sh index`,
showing which session owns which slice. Never hand-edit it.

## Session-start ritual (do these three steps in order, every session)

1. **Read the `.agent/handoffs/CURRENT.md` index** — the derived
   lab-wide view of which session owns which slice. Trust the per-slice
   status files over chat history. If the slice you'll work on shows a
   different `owner_agent` (not `claude`), also read
   `.agent/handoffs/takeover-prompt.md` and execute its steps before
   acting.
2. **Identify your slice and read its `.agent/status/<slice>.md`** —
   the authoritative per-slice baton (`owner_session`, `heartbeat`,
   `remaining_actions`, …). Find the slice from the index, or consult
   the `WORKFLOW.md §1` routing table if it isn't obvious. A session
   "claims" a slice via `owner_session` + `heartbeat`; the SessionStart
   hook warns if you enter a slice whose heartbeat is fresh under a
   different `owner_session` (contested slice). If the file is older
   than 7 days, prefer `./scripts/status.sh <slice>` for the live scan.
3. **Drill down only if the task needs more context** —
   `.agent/projects/<slice>-harness.md` for deep workflow detail. Do
   NOT pre-read all of them; pull on demand.

That's it. The previous 6-step ritual is collapsed into these three.
Working rules, approval gates, and verification commands live in
`AGENTS.md` — do not duplicate them here.

`.claude/skills/`.

## Memory policy

`~/.claude/projects/-home-ubuntu/memory/` (auto-memory) holds **user
profile, feedback, and external references only**. Project state lives
in `.agent/` exclusively — never duplicate it into auto-memory. The
`MEMORY.md` index header restates this rule; if you find yourself
about to write a `project_*.md`, write to `.agent/status/<slice>.md`
instead (never to the derived `CURRENT.md` index).

## End-of-session

When stopping, switching agents, or near context limit:
1. Update your slice's `.agent/status/<slice>.md` frontmatter + body
   (no `<placeholder>` fields). Write only your own slice's file.
2. Run `./scripts/handoff.sh claude <slice>` — bumps the frontmatter
   and snapshots git state under `.agent/handoffs/state/`.
3. Run `./scripts/status.sh index` to regenerate the derived
   `CURRENT.md` index. Never hand-edit `CURRENT.md`.
4. The Stop hook will warn if step 1 was skipped.

For full handoff field requirements see `.agent/handoffs/handoff.md`.
