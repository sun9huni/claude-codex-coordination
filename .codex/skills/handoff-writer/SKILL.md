# Handoff Writer

Chat history is not durable. Repo files are. This skill captures session
state into the active `.agent/status/<slice>.md` baton and refreshes the
derived `.agent/handoffs/CURRENT.md` index so any other agent can pick up
the work without trusting the chat.

## When to invoke

- Context budget below ~20%.
- Switching agent (e.g. Claude → Codex, Cursor → Claude).
- Pausing for human approval on an approval-gated action.
- Long-running job (SLURM, MMGBSA, ensemble) must outlive the chat.

## Workflow

1. Read `.agent/handoffs/handoff.md` and confirm trigger applies.
2. Identify the active slice from `.agent/handoffs/CURRENT.md`,
   `WORKFLOW.md`, or the task context. Read `.agent/status/<slice>.md`.
3. Update only that slice's `.agent/status/<slice>.md` with:
   - `owner_agent`, `owner_session`, `last_updated`, and `heartbeat`.
   - `state` — lifecycle field (`active` | `closed` | `released`).
     **Preserve if present**; do not flip it on a routine claim.
     `handoff.sh` itself preserves an existing `state` and only writes
     `state: released` via the `--release` verb. Codex sessions must
     follow the same rule.
   - Goal (observable), current status, and live-truth pointers in the body.
   - Files touched (real paths from your diff).
   - Verification command + result, or "not run" with reason.
   - Failure / error log absolute path, or "n/a".
   - 1–3 concrete remaining actions, ordered.
   - Approval-required list, or "none".
   - Contract and project-harness pointers.
4. Run `./scripts/handoff.sh <next-agent> <slice>` to claim/refresh the
   per-slice frontmatter. For terminal slice closure (work genuinely
   done), use `./scripts/handoff.sh --release <slice>` instead — it
   clears owner fields, sets `state: released`, and bumps `version`.
   Idempotent on an already-released slice. Do not use `--release`
   mid-session.
5. Run `./scripts/status.sh index` to regenerate the derived
   `.agent/handoffs/CURRENT.md` index. Do not hand-edit `CURRENT.md`.
6. Verify no `<placeholder>` strings remain in the slice status file.
7. Report to the human: the slice status path, the next agent name,
   and the one-line takeover instruction
   ("paste `.agent/handoffs/takeover-prompt.md` into the next agent").

## Guardrails

- Do not invent verification results. If you did not run it, say so.
- Do not paraphrase chat into the slice status as if it were ground
  truth. Only commit facts reproducible from the diff, logs, or
  filesystem.
- Do not hand-edit `.agent/handoffs/CURRENT.md`; it is a generated index.
- Do not write another slice's `.agent/status/<slice>.md` unless the user
  explicitly handed you that slice.
- Do not delete prior `archive/` or `state/` records without checking
  they are unreferenced by `.agent/contracts/`.
- Do not start a destructive or approval-gated action during a handoff.

## Output contract

The handoff is complete when:

- `.agent/status/<slice>.md` has no `<...>` placeholders and carries the
  current `remaining_actions`.
- `.agent/handoffs/CURRENT.md` was regenerated by `./scripts/status.sh
  index`.
- The remaining-actions list has at most 3 items.
- The human has been told one sentence: which agent takes over next and
  where to paste the takeover prompt.

## Notion sync (best-effort, warn-only, v0.5)

**Defensive Codex preamble — read first.** The Codex Notion MCP is NOT
guaranteed in every Codex runtime. So this whole section is gated on MCP
availability:

- **If the Codex Notion MCP is available this session**, reflect the
  active slice into Notion's three-DB IA (Slices DB / ADR Decisions /
  Experiments DB) per the sub-steps below, AFTER `./scripts/handoff.sh
  <agent> <slice>` (Workflow Step 4).
- **Else (MCP unavailable, unconfigured, or any sub-step errors)** →
  print a one-line warning to stderr and SKIP the Notion writes
  entirely. This step is **warn-only** and MUST NEVER block or fail the
  handoff. The durable record is already the workspace baton +
  `handoff.sh` snapshot (Workflow Steps 1–4); the source of truth lives
  in `.agent/`, and Notion is only the derived human view.

Best-effort, warn-only, non-blocking — by design. This is parity with
Claude's `/handoff` Step 5 (`/home/ubuntu/.claude/skills/handoff/SKILL.md`,
v0.5): same DB schema, same templates, same gate. The one difference is
the harder warn-only fallback above, because Codex cannot assume the MCP
is present. Like Claude, **writes are MCP-only / compute-then-apply** —
`notion_sync.py` only COMPUTES and PRINTS upsert-keyed payloads; you
APPLY them with the in-session Codex Notion MCP. The headless integration
token is blocked by workspace permissions, so never imply an automatic
headless network write. Reference Notion targets by `.agent/notion_map.yaml`
`v0_5:` KEYS, never by raw UUID.

The seven sub-steps below wrap the preserved v0.4.2 lab-log (points 5–6)
with the v0.5 DB updates (points 2–4):

1. **Get the payloads** (no Notion calls yet):

   ```
   /home/ubuntu/miniconda3/bin/python /home/ubuntu/scripts/notion_sync.py \
     --handoff-log --slice <slice>          # v0.4.2 lab-log payload
   /home/ubuntu/miniconda3/bin/python /home/ubuntu/scripts/notion_sync.py \
     --migrate slices                        # Slices DB rows
   ```

   `--handoff-log` yields `{date, iso_week, conclusion, change_digest,
   evidence, event_type, event_emoji, event_color}`; the last 3 drive the
   callout's visual rendering (see `classify_event(conclusion)` in
   `scripts/notion_sync.py`). For the v0.5 DB updates use
   `slice_to_db_row(<slice>)` (via `--migrate slices`) and — only on the
   transitions in point 3 — `contract_to_adr_rows(<contract_path>)` (via
   `--migrate contracts`).

2. **Slices DB row** — find the active slice's row by
   `notion_map.yaml` `v0_5:slice_row_ids[<slice>]` and update it (MCP
   page-update) with `slice_to_db_row(<slice>)`. This maps `state:` →
   Status (활성 / 완료 / 릴리즈 / 휴면 via `slice_to_db_row`) and refreshes
   Owner / Last Heartbeat / Last Updated / Next Action — **and you MUST also
   push the 8 cockpit fields the payload carries: Headline / Now /
   Decision Needed / Agent Next / Blocker / Health / Sync Status /
   Last Sync Source (they drive the Navigator action queues; pushing only
   the core fields re-blanks Health/Decision/Agent next handoff).** (upsert
   key = `Name`). Uses `v0_5:slices_db_id` / `v0_5:slices_db_data_source_id`
   from the map — reference by these keys, never paste raw UUIDs.

   **Rendered home page (Task 18, SHIPPED):** also refresh the Navigator home —
   run `./scripts/notion_sync.py --render-home` and apply the printed body via one
   MCP `replace_content` on the home page (it self-aborts with `HOME_RENDER_UNSAFE`
   if any child page/DB would drop). Then run
   `./scripts/notion_sync.py --stamp-home-applied` to record the apply — the Stop
   hook uses the stamp to warn `[home-stale]` if a baton later changes, and it lints
   the active baton as `[baton-lint]` (both non-blocking). Do this whenever a slice
   changed materially this session so the home stays accurate.
   `handoff.sh` auto-drops a `.agent/handoffs/state/notion-sync-pending` marker, and
   `/home/ubuntu/scripts/notion_sync.py --handoff-emit <slice>` is the one-shot way to
   get the home body + that slice's row payload in one block; the next MCP session
   auto-applies a pending sync (the `⚠️ NOTION SYNC PENDING` SessionStart directive)
   and `--stamp-home-applied` clears the marker. If THIS Codex session lacks the
   Notion MCP, do not apply anything — the marker simply persists for the next Claude
   session to catch up (cross-session catch-up).

3. **ADR rows (conditional)** — ONLY if this handoff was triggered by a
   contract `status:` transition (`pending→approved` or `approved→done`),
   run `contract_to_adr_rows(<contract_path>)` and create/update the ADR
   rows in the Decisions data source (`v0_5:decisions_data_source_id`),
   one row per `decisions:` item (upsert key = `adr_id`). Status maps
   Proposed / Accepted / Implemented. If no such transition occurred,
   SKIP this step.

4. **Experiments scan (optional)** — if new mmgbsa SLURM jobs completed
   since the last handoff, run `--migrate slurm` and upsert the affected
   Experiments DB rows (`v0_5:experiments_db_id`, upsert key = `Run ID`).
   Skip if nothing new completed. No daemon / no live monitor.

5. **Slice hub `〔sync〕` block** (preserved v0.4.2) — on the slice's hub
   child page, replace or insert a `<details color="<slice_bg>">` TOGGLE
   colored to match the slice. Summary line `🔄 **동기화** · <date> ·
   자동 생성 ...`; body is the 4-row table (상태 / 진행 중 / 다음 / 갱신).
   Find-or-update by matching `🔄 **동기화**`. Slice color comes from
   `.agent/notion_map.yaml`.

6. **Weekly Digest row** (preserved v0.4.2) — find/create `<slice>
   <iso_week> Weekly Digest` in the Reports DB (Report Type=Weekly Digest,
   Slice=<slice>, Date=Monday of ISO-week). **Change-gated**: only insert
   a new EVENT-TYPED CALLOUT when the payload's `change_digest` is NOT a
   substring of the most-recent callout body (the chg-digest gate); else
   idempotently update today's callout. Insert most-recent first, using
   `event_emoji` as icon and `event_color` as color:
   ```
   <callout icon="<event_emoji>" color="<event_color>">
   **<event_type> · <MM-DD>** — <one-line title>
   <identifier line>
   <body line(s)>
   **다음**: <next action>
   <span color="gray">chg:<change_digest></span>
   </callout>
   ```

7. **NON-BLOCKING / warn-only** (preserved, Codex-hardened) — if the
   Codex Notion MCP is unavailable or ANY sub-step errors, emit a
   one-line stderr warning and STOP the sync. Do NOT raise — the handoff
   MUST complete regardless. The durable record is the slice file +
   `handoff.sh` snapshot from Workflow Steps 1–4; Notion is the derived
   human view. No format divergence between Claude and Codex by design.
